# 04 · 腹部实验：从训练到推理的全过程

> 这一篇把「一批原始采集 → 可用的模型 → 测试数字」整条链路走一遍，腹部当例子。
> 手心、腿部照抄这一篇，只改数据路径和深度范围。
> 数据总账见 `Resource/README.md`，第二/三阶段（手背）见 `02-Multi-YOLO-RGB.md` / `03-YOLO26-自生成深度对比.md`。

## 1. 为什么单独做腹部

手背是 7 个关键点、近距离、单部位。老师要求「不同部位往下做」，腹部是第二个部位（3 个关键点）。
它能验证一件事：**手背上得到的结论（4 通道改造、深度用法）是不是只在手部成立。**

## 2. 数据准备

### 2.1 原始数据长什么样

```
Resource/abdomen/raw/abdomen_133/
  image/    color_<时间戳>.png     133 张 RGB（1280×720）
  depth/    <时间戳>.jpg           彩色化预览图（给人看，不能训练）
  npy/      depth_<时间戳>.npy     真实深度，uint16，单位毫米
  labels/   color_<时间戳>.txt     YOLO-Pose 标签，3 个关键点
```

**三个文件名必须带前缀**：RGB 要 `color_`，深度要 `depth_`，标签要 `color_`。
`prepare_pose_rgbd_dataset.py` 是靠「去掉前缀剩下的时间戳」配对的，没前缀 → 样本数 0。

### 2.2 深度编码范围：必须先量，不能照抄

手背用 `clip(1100, 1850) mm`，**腹部完全不能用**——腹部深度只有 255~589mm，
按 1100 起算会把整层压成 1（纯黑），深度信息全废。

量法（20 行，见下方命令）：读一张图的 npy，排除 0 和 65535，取 2% / 98% 分位。

```
腹部 133 张实测：1% = 256mm，2% = 257mm，98% = 566mm，99% = 586mm
选定：low = 250，high = 600
```

编码公式（脚本内部实现，不用手算）：

```
invalid (0 或 65535)  → ch4 = 0
valid                 → ch4 = 1 + (clip(d, 250, 600) − 250) × 254 / 350
```

**腹部的特点**：每张图的深度跨度差异极大（最窄 49mm，最宽 2331mm）。
固定范围编码后，跨度窄的图只占中间一小段。这点已记进 `Resource/README.md` 的已知问题。

### 2.3 跑数据准备脚本

```powershell

  --depth_npy_dir "H:/YJJ/Yolo_RGBD/Resource/abdomen/raw/abdomen_133/npy" ^
  --label_dir     "H:/YJJ/Yolo_RGBD/Resource/abdomen/raw/abdomen_133/labels" ^
  --output_dir    "H:/YJJ/Yolo_RGBD/Resource/abdomen/datasets/abdomen_dataset" ^
  --class_name abdomen --depth_low 250 --depth_high 600
```

产物：

```
abdomen_dataset/
  rgb/{images,labels}/{train,val,test}     3 通道
  rgbd/{images,labels}/{train,val,test}    4 通道
  splits.json          train 93 / val 20 / test 20（按时间戳升序 70/15/15，不随机）
  dataset_report.json  GUI「使用已有数据集」读这个
```

### 2.4 这一步踩过的三个坑

| 坑 | 现象 | 处理 |
|---|---|---|
| 深度目录指到 `depth/`（彩色预览图） | 融合出来是一张假彩图当深度 | 必须指 `npy/` |
| 深度范围照抄手部 1100~1850 | ch4 全变 1，等于没有深度 | 按 2.2 重新量 |
| 文件名裸时间戳无前缀 | `[STOP] 测试集里没有图片` 或样本数 0 | 补 `color_` / `depth_` 前缀 |
| 保真校验 `Spearman > 0.999` 过不去 | `AssertionError: P=0.9999 S=0.9989` | 腹部深度跨度窄、uint8 量化后并列多，天然到不了 0.999；临时把阈值放宽到 0.99 跑（主仓脚本未改） |

## 3. 训练

### 3.1 两组实验的起点权重

| 组 | 起点 | 为什么 |
|---|---|---|
| RGB（3 通道） | `weights/yolo11n-pose.pt`（官方） | 标准做法 |
| RGBD（4 通道） | `yolo11_4ch/yolo11n-pose_4ch.pt`（改造版） | 首层要能吃 4 层 |

4 通道改造规则：第一层输入 3→4，**第 4 个输入通道权重 = RGB 三通道权重的平均**。

### 3.2 命令

```powershell
# RGB（3 通道）
.venv\Scripts\python.exe YJJ_Pose_Scripts\03_train\train_rgb_pose.py ^
  --data <...>\abdomen_dataset\rgb\data_rgb.yaml ^
  --weights weights\yolo11n-pose.pt --fliplr 0.0 --patience 20

# RGBD（4 通道）
.venv\Scripts\python.exe YJJ_Pose_Scripts\03_train\train_rgbd_pose.py ^
  --data <...>\abdomen_dataset\rgbd\data_rgbd.yaml ^
  --weights yolo11_4ch\yolo11n-pose_4ch.pt --fliplr 0.0 --patience 20 --name train_yolo11n_abdomen_rgbd
```

`train_rgb_pose.py` **没有 `--name` 参数**，输出目录固定叫 `runs/pose/train_pose_rgb_3ch`，
再训一次会覆盖——要保留旧结果就先复制走。

### 3.3 固定超参

| 项 | 值 | 说明 |
|---|---|---|
| epochs | 120（上限） | 早停会提前结束 |
| patience | 20 | 验证集 20 轮不涨就停 |
| batch | 4 | 8GB 显存够用 |
| imgsz | 640 | 与推理一致 |
| fliplr | 0.0 | **关键点有左右语义，翻转会毁标签** |
| 其余增强 | 基本关闭 | 小数据集，增强容易过拟合 |

## 4. 评估

### 4.1 口径（全项目统一）

```
conf = 0.05，imgsz = 640
命中：预测框与标注框 IoU ≥ 0.50（取 IoU 最大的那个预测）
定位误差 NME = 7 个点（这里是 3 个）的像素误差 ÷ 标注框对角线，
             只算 visibility>0 的点，逐图平均，再对全部测试图平均
引用格式：0.020831（腹部 20 张，conf=0.05，命中 20/20）
```

腹部测试集只有 **20 张**，是手背 100 张的五分之一，结论要按小样本看待。

### 4.2 命令

```powershell
.venv\Scripts\python.exe test_all.py ^
  --dataset-root "H:/YJJ/Yolo_RGBD/Resource/abdomen/datasets/abdomen_dataset" ^
  --weights train_weight\yolo11n_abdomen_rgb.pt train_weight\yolo11n_abdomen_rgbd_v2.pt ^
  --conf 0.05 --output-dir runs\test_abdomen
```

## 5. 结果

### 5.1 主表（腹部 test 20 张，全部 20/20 命中）

| 模型 | 第 4 层 | 定位误差 | 相对 3 通道 |
|---|---|---|---|
| 3 通道 RGB | 无 | 0.028140 | — |
| **4 通道（从 3 通道权重改造起步）** | 真实深度 | **0.020831** | **−26.0%** |
| 4 通道（从通用 4 通道起点） | 真实深度 | 0.095627 | +239.8% |
| 3 通道继续训（对照） | 无 | 0.042892 | +52.4% |

**结论（人话）**：腹部上**深度是有用的**，降 26%；但**起点选错会把模型训坏**（0.0956，比 3 通道差 3.4 倍）。

### 5.2 为什么加了两行“对照组”

第一版 4 通道（从通用 4 通道起点训）只有 0.0956，看着像“深度有害”。但有两个混淆：

1. 起点不同（通用 4 通道权重 vs 官方 3 通道权重）；
2. 第二版 4 通道是**从腹部 3 通道权重继续训了 27 轮**，涨的可能只是“多训了”。

所以补了「3 通道继续训」这一行：**同起点、同数据、只多训**，结果 0.0429（更差）。
→ 排除“多训”这个解释，4 通道的 0.0208 确实是深度带来的。

### 5.3 深度敏感度（在 0.0208 那个模型上跑 34 项）

| 改动 | 变化 | 说明 |
|---|---|---|
| 深度清零（ch4 全 0） | −0.3% | **几乎无影响**：模型把 0 当“没有深度”，优雅降级 |
| 像素整体打乱 | −4.0% | 结构被打乱也不影响 → 不依赖空间细节 |
| 填成一块平均值 | +2.1% | 噪声级 |
| 上下镜像 | +3.2% | 噪声级 |
| **深度整体反转** | **+76.3%** | 方向反了 → 明显变差，说明它在用"远近方向" |
| **深度填 128 / 200** | **+24.4% / +45.7%** | 电平被换掉 → 变差 |
| 只留边缘 | +2.3% | 不影响 → 不看细节 |
| 第 1 层输出 ×0.5 | +53.8% | 手背上“调暗第 1 层更好”，腹部**相反** |
| 换成原图黑白 | −11.2% | 换成亮度反而更好（与手背 11 一致） |
| RGB 三通道反转 | +449.9%（只剩 4 命中） | 颜色不能动 |

**读法**：腹部模型用的也是“**深度整体电平 + 远近方向**”，不看细节、不看结构；
但和手背的 YOLO11 不同——手背上“反转深度 / 调暗第 1 层”能变好，**腹部上这两件事都变差**。

## 6. 推理（单张）

模型训完就是普通的 ultralytics 权重，4 通道的要注意**必须读成 4 层**：

```python
import cv2
from ultralytics import YOLO

model = YOLO(r"train_weight\yolo11n_abdomen_rgbd_v2.pt", task="pose")
img = cv2.imread(r"H:\...\abdomen_dataset\rgbd\images\test\color_xxx.png", cv2.IMREAD_UNCHANGED)
assert img.shape[2] == 4, "4 通道模型必须喂 4 层图"

result = model(img, conf=0.05, imgsz=640)[0]
print(result.boxes.xyxy)          # 框
print(result.keypoints.data)      # 3 个关键点 (x, y, 置信度)
```

- 3 通道模型喂 `rgb/images/...` 的 jpg 即可；4 通道模型**必须**喂 `rgbd/images/...` 的 png。
- **第 4 层不能自己拼**：编码规则（low/high）必须和训练时一致，否则输出全错。

> 仓库里的 `05_infer/infer_pose_image.py` 是硬编码示例（路径和权重写死），只能当参考，
> 正式批量推理用 `test_all.py`。

## 7. 换下一个部位（手心）要抄哪几步

| 步 | 做什么 | 对应本文 |
|---|---|---|
| 1 | 确认原始数据三类文件齐全（image / npy / labels） | 2.1 |
| 2 | 量该部位的深度 2% / 98% 分位，定 low/high | 2.2 |
| 3 | 补文件名前缀（`color_` / `depth_`） | 2.4 |
| 4 | 跑 `prepare_pose_rgbd_dataset.py` | 2.3 |
| 5 | 3 通道先训一个（拿到该部位的“基线权重”） | 3.2 |
| 6 | **把这个基线权重改造成 4 通道**，再训 4 通道 | 3.2 + 5.1 |
| 7 | 两组一起 `test_all.py` 对比 | 4.2 |
| 8 | 在这个部位的 4 通道模型上跑 34 项深度矩阵 | 5.3 |

**第 6 步是这次学到的关键**：不要从通用 4 通道起点直接训小部位数据，坏解风险很高。

---

## 8. 边界

1. 腹部测试集只有 **20 张**，比手背的 100 张少得多，结论按小样本看待。
2. 单 seed，未做重复训练方差。
3. 深度编码用固定 `250~600mm`，而每张图跨度差异很大（49~2331mm），窄跨度图的深度分辨力偏低。
4. `−26%` 这个结论只在“从 3 通道权重改造起步”这一种训练方式下成立，换起点不成立（5.1 第二行）。
5. 34 项矩阵里“清零 −0.3%”“打乱 −4.0%”说明模型对深度缺失是优雅降级的，
   但**不等于它没用深度**——反转 +76%、换电平 +24% 都证明它在用。
